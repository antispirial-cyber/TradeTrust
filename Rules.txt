TRADETRUST — RULES
==================

These are the non-negotiables. Read before writing any code.


SYLLABUS RULES (hardest constraints)
-------------------------------------
This is a Mumbai University Sem 3 academic project. The tech stack is fixed.

- Database: raw JDBC only. java.sql.* — DriverManager, PreparedStatement,
  ResultSet. No Hibernate. No JPA. No Spring Data. No ORM of any kind.
  Every SQL query is written by hand.

- Backend: explicit Servlet classes extending HttpServlet. Every Servlet
  implements doGet() and doPost() explicitly. init() and destroy() must
  exist even if empty. Spring Boot is the wrapper but the Servlet code
  is written out in full, not hidden behind annotations.

- Frontend: React only. No JSP. No Thymeleaf. No server-side HTML.
  All UI is React functional components using hooks.

- No libraries outside the approved list without written permission from
  the project coordinator. If something outside the list is genuinely
  needed, mark it with a comment: OUTSIDE-SYLLABUS: [name] — reason: [why]

Approved list: React 18, React Router DOM v6, Spring Boot 3,
MySQL Connector/J, Jakarta Servlet API, Maven.


SECURITY RULES
--------------
- Always use PreparedStatement. Never build SQL strings by concatenation.
- Hash passwords. Never store plain text. BCrypt preferred, SHA-256 acceptable.
- Validate all input on the backend. Frontend validation is UX only.
- Check session and role at the start of every Servlet method.
  Traders cannot touch admin routes. Traders cannot touch each other's data.
- Validate file uploads by MIME type AND extension. Reject anything
  that is not JPG, PNG, or PDF. Rename files on save. Never execute uploads.


CODE STRUCTURE RULES
--------------------
- Servlet handles HTTP only. No SQL in Servlet classes.
- DAO handles all database operations. One DAO per table.
- Model is a plain Java object matching the table structure.
- Util has shared helpers: DBConnection, PasswordUtil, SessionUtil, ScoreUtil.

Naming:
  Java classes     PascalCase      (TraderDAO, AuthServlet)
  Java methods     camelCase       (getTraderById)
  Database tables  snake_case      (trader_id, created_at)
  React components PascalCase      (ScoreRing.jsx, TraderCard.jsx)
  API endpoints    kebab-case      (/api/trader-profile)
  CSS classes      kebab-case      (score-ring, trader-card)


FRONTEND RULES
--------------
- Functional components only. No class components.
- Hooks: useState, useEffect, useContext, useRef. No lifecycle methods.
- All fetch() calls go in /src/api/ files. Components import and call
  those functions. No inline fetch() inside components.
- All colors are CSS custom properties in variables.css.
  No hardcoded hex values in component CSS.
- No inline style={{}} in JSX except for values computed at runtime
  (like the score ring gradient which needs to be calculated dynamically).
- All pages must work on a 375px mobile screen.
  Use flexbox or grid. No fixed pixel widths on containers.


DATABASE RULES
--------------
- No stored procedures. All logic lives in Java.
- Declare all foreign key constraints in schema.sql.
- created_at: set on INSERT, never updated.
- updated_at: use ON UPDATE CURRENT_TIMESTAMP.
- Do not hard-delete complaints. Add is_deleted flag if needed.
  Ledger entries can be hard-deleted (they are private user data).


DO NOT BUILD
------------
- WebSockets or any real-time feature
- Email or SMS notifications
- Payment processing
- OAuth or social login
- AI or ML features
- Data export
- Cross-cluster search (V3)
- Auto-escalation timer (V2)
- Public API for third parties
