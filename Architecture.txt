TRADETRUST — ARCHITECTURE
=========================

THE STACK
---------
Frontend  : React 18, React Router DOM v6, plain CSS with custom properties
Backend   : Java 17, Spring Boot 3, Jakarta Servlet API, raw JDBC (java.sql.*)
Database  : MySQL 8 on port 3306, database name: tradetrust_db
Server    : Embedded Tomcat via Spring Boot on port 8080
Dev       : React dev server on port 3000, proxied to 8080


HOW IT FITS TOGETHER
--------------------
Browser calls React (port 3000).
React calls Spring Boot REST API (port 8080) using fetch().
Spring Boot Servlets handle requests, call DAOs, which use raw JDBC to hit MySQL.
Files (proof uploads, shop photos) are saved on the server filesystem.
File paths (strings) are stored in MySQL, not the files themselves.


JDBC — THE 7 STEP FLOW
-----------------------
Every database operation follows this exactly:

1. import java.sql.*;
2. Class.forName("com.mysql.cj.jdbc.Driver");
3. Connection con = DriverManager.getConnection(URL, USER, PWD);
4. PreparedStatement ps = con.prepareStatement("SELECT ...");
5. ps.setString(1, value);
6. ResultSet rs = ps.executeQuery();  // or ps.executeUpdate() for writes
7. rs.close(); ps.close(); con.close();  // always in finally block

Connection string:
  String URL  = "jdbc:mysql://localhost:3306/tradetrust_db";
  String USER = "root";
  String PWD  = "your_password";

IMPORTANT: Port is 3306. Not 3036. That is a common typo. Use 3306.

Always use PreparedStatement. Never concatenate user input into SQL strings.
Put all JDBC code in DAO classes. Servlets never write SQL directly.


SERVLET STRUCTURE
-----------------
Each feature group has one explicit class extending HttpServlet.
Every class implements doGet() and doPost() and has init() and destroy().

AuthServlet       POST /api/auth/register, /api/auth/login, /api/auth/logout
TraderServlet     GET  /api/trader/{id}, PUT /api/trader/update
BrowseServlet     GET  /api/browse  (params: cluster, sector, role, search, page)
ComplaintServlet  POST /api/complaint/file, /api/complaint/counter
                  GET  /api/complaint/{id}, /api/complaint/my
LedgerServlet     GET/POST/PUT/DELETE  /api/ledger, /api/ledger/{id}
ConnectionServlet POST /api/connect/request, /api/connect/respond
                  GET  /api/connect/list
NotificationServlet GET /api/notifications, PUT /api/notifications/read
ScoreServlet      GET  /api/score/{traderId}
UploadServlet     POST /api/upload
AdminServlet      POST /api/admin/login, GET /api/admin/complaints
                  POST /api/admin/verdict, /api/admin/broadcast


DATABASE SCHEMA
---------------

traders
  trader_id            INT AUTO_INCREMENT PRIMARY KEY
  name                 VARCHAR(100) NOT NULL
  phone                VARCHAR(15) NOT NULL UNIQUE
  business_name        VARCHAR(150) NOT NULL
  business_desc        TEXT
  role                 ENUM('WHOLESALER','RETAILER') NOT NULL
  cluster              VARCHAR(100) NOT NULL
  sector               VARCHAR(100) NOT NULL
  photo_path           VARCHAR(255)
  password_hash        VARCHAR(255) NOT NULL
  trust_score          DECIMAL(4,2) DEFAULT 10.00
  score_frozen         BOOLEAN DEFAULT FALSE
  score_before_freeze  DECIMAL(4,2)
  is_verified_badge    BOOLEAN DEFAULT FALSE
  created_at           DATETIME DEFAULT CURRENT_TIMESTAMP

complaints
  complaint_id     INT AUTO_INCREMENT PRIMARY KEY
  reporter_id      INT NOT NULL  -- FK to traders
  reported_id      INT NOT NULL  -- FK to traders
  description      TEXT NOT NULL
  amount_disputed  DECIMAL(12,2)
  incident_date    DATE NOT NULL
  proof_path       VARCHAR(255)
  status           ENUM('ROUND_1_PENDING','ROUND_1_COUNTER_FILED',
                        'ROUND_2_PENDING','ROUND_2_COUNTER_FILED',
                        'ESCALATED_TO_ADMIN','APPROVED','REJECTED')
                   DEFAULT 'ROUND_1_PENDING'
  created_at       DATETIME DEFAULT CURRENT_TIMESTAMP
  updated_at       DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

complaint_rounds
  round_id      INT AUTO_INCREMENT PRIMARY KEY
  complaint_id  INT NOT NULL  -- FK to complaints
  filed_by      INT NOT NULL  -- FK to traders
  round_number  INT NOT NULL
  description   TEXT NOT NULL
  proof_path    VARCHAR(255)
  filed_at      DATETIME DEFAULT CURRENT_TIMESTAMP

ledger_entries
  entry_id    INT AUTO_INCREMENT PRIMARY KEY
  owner_id    INT NOT NULL  -- FK to traders
  party_name  VARCHAR(150) NOT NULL
  amount      DECIMAL(12,2) NOT NULL
  entry_type  ENUM('CREDIT_GIVEN','CREDIT_RECEIVED') NOT NULL
  entry_date  DATE NOT NULL
  description TEXT
  status      ENUM('PENDING','PAID','OVERDUE') DEFAULT 'PENDING'
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP

connections
  connection_id  INT AUTO_INCREMENT PRIMARY KEY
  requester_id   INT NOT NULL  -- FK to traders
  receiver_id    INT NOT NULL  -- FK to traders
  status         ENUM('PENDING','ACCEPTED','DECLINED') DEFAULT 'PENDING'
  created_at     DATETIME DEFAULT CURRENT_TIMESTAMP
  UNIQUE (requester_id, receiver_id)

notifications
  notification_id  INT AUTO_INCREMENT PRIMARY KEY
  recipient_id     INT NOT NULL  -- FK to traders
  type             VARCHAR(50) NOT NULL
  message          TEXT NOT NULL
  link_ref         VARCHAR(255)
  is_read          BOOLEAN DEFAULT FALSE
  created_at       DATETIME DEFAULT CURRENT_TIMESTAMP

admins
  admin_id       INT AUTO_INCREMENT PRIMARY KEY
  username       VARCHAR(50) NOT NULL UNIQUE
  password_hash  VARCHAR(255) NOT NULL

trader_settings
  setting_id    INT AUTO_INCREMENT PRIMARY KEY
  trader_id     INT NOT NULL UNIQUE  -- FK to traders
  accent_color  VARCHAR(7) DEFAULT '#4A90E2'


TRUST SCORE FORMULA
-------------------
Starting score: 10.00

When a complaint is approved, deduct:
  base deduction = 2.0
  + 0.0 if amount < 5000
  + 0.5 if amount 5000 to 25000
  + 1.0 if amount 25000 to 100000
  + 1.5 if amount > 100000

Score never goes below 0.00.

When complaint is rejected: restore score_before_freeze value.
After any verdict: recalculate is_verified_badge.
Badge = TRUE if no approved complaints in past 12 months AND account age > 3 months.


SESSION MANAGEMENT
------------------
Login generates a UUID token stored in HttpSession server-side.
Token returned to React, stored in React context (not localStorage).
Every API request sends: Authorization: Bearer <token>
Backend validates token and extracts trader_id from session.
Admin has a separate session checked on all /api/admin/* routes.


FILE UPLOADS
------------
Spring Boot MultipartFile handles incoming files.
Shop photos saved to:  /uploads/photos/{trader_id}_{timestamp}.{ext}
Complaint proof saved: /uploads/proofs/{complaint_id}_{timestamp}.{ext}
Relative path stored as string in MySQL.
Files served as static resources via Spring Boot config.
Accepted types: image/jpeg, image/png, application/pdf
Max size: 5MB (set in application.properties)


API RESPONSE FORMAT
-------------------
Every endpoint returns JSON in this shape:

Success:
{ "success": true, "data": { ... }, "message": "optional" }

Error:
{ "success": false, "error": "ERROR_CODE", "message": "what went wrong" }

HTTP codes: 200 success, 201 created, 400 bad request, 401 unauthorized,
            403 forbidden, 404 not found, 500 server error
